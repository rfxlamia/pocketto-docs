---
title: Core & Enterprise
description: How the local-first Core and the optional Enterprise adapter split ownership of state and GitHub.
---

Pocketto splits into two independently installed pieces with a hard ownership boundary:

- **Core** is local-first. It commits lifecycle state and neutral events locally and **never calls `gh`**: it does not create or reconcile GitHub resources, does not merge pull requests, and does not close issues.
- **Enterprise** is a separately installed, opt-in **adapter**. It consumes Core's durable events and owns *all* remote reconciliation: the approved-spec issue, phase PR summaries and findings, stacked phase PR publication, and the final tasklist. It is fail-closed before any remote operation and never merges a PR or closes an issue. Humans keep those gates.

Missing or incompatible Enterprise never blocks Core work: events remain durable locally for later replay.

## The compatibility matrix

| Core | Enterprise | Result |
|------|------------|--------|
| v3 Core + v3 Enterprise | v3 | Legacy pair remains operational with a v4 upgrade warning. |
| v4 Core + v4 Enterprise | v4 | Supported split and lifecycle contract. |
| v4 Core + absent Enterprise | none | Supported local-first Core; events remain pending and no GitHub call occurs. |
| v3 Core + v4 Enterprise | v4 | Enterprise fails closed with Core upgrade guidance; Core remains usable. |
| v4 Core + v3 Enterprise | v3 | Adapter fails closed with Enterprise upgrade guidance; pending events are preserved. |
